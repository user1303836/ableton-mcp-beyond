# Capability and evidence matrix

English · [简体中文](../zh-CN/CAPABILITY_MATRIX.md) · [日本語](../ja/CAPABILITY_MATRIX.md)

The version-controlled source of truth for what the agent can do in Ableton
Live, and how far each claim is evidenced. “Implemented” never means “proved in
every external environment.”

## What can the agent do?

Plain-language answers for producers. Every mutation runs through a read-only
preview, your explicit confirmation, an exact apply, and a verified read-back;
most content edits can be undone with `live_undo`.

## Evidence scope

- **unit/property/simulator** — deterministic repository contract only;
- **packaged fake-Live** — installed tarball, authenticated cross-process bridge,
  deliberately fake Live provenance;
- **real-Live** — authenticated Remote Script observation in the named disposable
  Live environment; and
- **host matrix** — Node/package/lifecycle behavior, never Windows Live.

Safety classes: **R** read-only; **G** revision/epoch-bound preview-confirm-verify
mutation; **A** audible or recording with output/recording gates and independent
stop; **RT** short-lived realtime authority; **FS** owner/allowlist-bound
filesystem mutation; **P** consent/privacy-sensitive audio; **D** delivery and
installation authority.

## Evidence freshness rule

Tracked phase evidence proves the named historical phase and environment. It is
not silently promoted to a later artifact. Final readiness additionally
requires the pushed-head CI artifact metadata, exact-candidate host results, and
an externally retained real-Live observation naming that same Git SHA and
artifact SHA-256. Windows Server host evidence never fills a Windows
Live/Windows 11 cell.

## Executable versus reserved registry contracts

The canonical registry contains more operation IDs than the mapper currently
advertises. Only negotiated, executable operations appear in `live_status` /
`capabilities` under `operations.executable`; the remainder
(`operations.reserved`) are strict contracts that fail closed until an adapter
can execute and verify them. Reserved IDs are never evidence of a working
capability.

| Operation IDs | Disposition |
|---|---|
| `audio.warp-marker.read/add/move/delete` | Implemented and executable when the connected Live shape advertises the exact operations; schemas address markers by beat time — no invented integer IDs |
| `audio.take-lane.read`, `audio.comp.read` | `audio.take-lane.read` is implemented when negotiated. The public MCP surface exposes discovery, rename, and file-backed audio import for existing lanes; mapper-only lane creation and MIDI lane-clip paths are not advertised. `audio.comp.read` remains reserved because the public LOM exposes no comp-region API |
| `arrangement.automation.*` | Arrangement automation authoring has no stable public API; stays reserved and fail-closed |
| `browser.preview.start/stop` | Explicitly declined for the current Remote Script: the unofficial binding has no authoritative observable preview state, so these contracts remain reserved and fail closed |
| `project.new/open/save/save-as/collect/export/bounce` | No public Remote Script API; the limitations are reported through the capability resource's `limitations` section, never through callable tool discovery |
| `session.discover` | Reserved alias; discovery is served by `discover`/`snapshot`/`get` |
