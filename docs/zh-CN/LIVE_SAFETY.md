# Ableton Live 安全

[English](../en/LIVE_SAFETY.md) · 简体中文 · [日本語](../ja/LIVE_SAFETY.md)

每一次 Live 交互都必须遵守的安全契约。把服务器连接到真实 Set 之前请先
阅读本文。

默认适配器是 `UnavailableLiveAdapter`:断开连接、不进行任何 Live I/O,
并且不能通过调用方元数据、MCP 参数、模拟器输出或磁盘上存在 Live 来
选择。生产桥接需要显式的回环配置、owner-only 密钥、匹配的协议/注册表,
以及已报告的操作能力。

## 部署信任边界

本项目支持由所有者控制、仅限本地回环的部署。它信任本地 OS 账户和 MCP
客户端的审批策略。服务器无法独立证明确认或输出安全声明来自人类,而不是
发出请求的同一模型;项目不提供带外 arming 界面。请勿自动批准发声、录音、
路由、捕获或实时工具。对于无人值守客户端,请使用客户端拒绝规则或不配置
生产桥接,并且只在可丢弃的 Set 中工作。

## 通用变更边界

每一项变更都要求:

- 新鲜的已认证状态与精确协商的操作;
- 权威的、绑定 epoch 的引用与状态;
- 有界输入与用途特定的授权;
- 适用时的只读预览;
- 精确确认、有效期与幂等性;
- 在 Live 主线程上的原子前置条件复检;
- 新鲜的事后验证;
- 仅事务自有的补偿/撤销/清理;
- 超时、确认丢失、外部编辑、验证失败或清理失败后的明确**不确定**状态。

客户端绝不得用新的预览或键来替代不确定的授权。在同一桥接与 Live epoch
内,宿主只能依据 Remote Script 账本应答原事务/键/参数,然后进行新鲜的事后
验证。不支持的属性或枚举值属于不可用证据,而不是安全的默认值。

认证不等于变更授权。在每次变更性的桥接 `invoke` 之前,生产适配器会执行
只读的 `authority.preflight`,通过 `authority.prepare` 回显其不可预测的
一次性确认,并获得一个一次性、10 秒有效的令牌,绑定到精确的操作/参数
摘要、连接 epoch、新鲜的权威目标值、播放/录音状态、被引用对象的修订以及
Session 结构。桥接在 Live 线程分发前消费该令牌,并拒绝直接的已认证变更
帧、preflight 或令牌重放、猜测的确认、不匹配的参数、过期以及其间发生的
状态变化。桥接在 TCP 重连之间保留有界的已执行结果账本,因此丢失的响应
可以被精确对账,而不是盲目重放。可发声启动、捕获开始、录音与实时布防
契约还会在桥接侧重新核验输出安全证据。

## 已实现的变更类别

受护栏的工作流覆盖:走带;剪辑启动与精确停止;MIDI 剪辑与音符;
Arrangement 剪辑与定位点;混音器与路由;Session 自动化;设备与 Browser
加载;Session/Arrangement 录音;工程备份;实时控制;以及知情同意的音频
捕获。每一类在其用户/运维文档中都有更严格的检查。

- Session 结构创建返回精确的对象身份;补偿与撤销会复检这些身份,并调用
  Live 的索引删除 API,而不是删除陈旧的代理或被复用的路径。
- `live_undo` 是事务特定的,拒绝已变化的 epoch 或事后状态。
- 任意删除设备或 Arrangement 剪辑不可用:清理要求精确的、由事务创建的
  对象身份、层级与创建时指纹,并拒绝被修改或替换的对象。
- 设备插入与 Browser 加载要求空的精确设备所有者,且清理要求所创建的
  设备仍是其唯一同级,因此索引删除绝不会选中无关的同级设备。
- 移动绝不产生破坏性清理授权:预先存在的剪辑在移动后仍是预先存在的;
  源与目标内容指纹受到隔离;恢复只使用精确的、未变化的逆移动事务。
  移动一个由事务创建的剪辑会原子地消费其先前的清理令牌,而不为移动
  结果授予新的删除权。
- MIDI 捕获仅在所有 Session 槽位为空时才宣告,因此部分失败的 Capture
  MIDI 实现不可能在没有精确恢复路径的情况下改变预先存在的剪辑内容。

只读操作包括:状态、能力协商、快照、发现、预览、工程检查、订阅读取、
实时统计、调用方 PCM 分析/参考对比,以及调用方声明的 Live 上下文诊断。
只读工具绝不启动播放或录音。

## 可发声的 Session 操作

场景/剪辑启动要求:明确的输出安全证据、精确的合格目标、停止且未录音的
基线、安全的监听/arm 状态、新鲜的播放修订、有界的启动量化,以及在预览
中捕获并携带到 Live 线程上复检的轨道/场景/槽位/剪辑身份。自有停止只清除
预先检查的目标;`live_session_emergency_stop` 独立地要求精确的新鲜活跃
目标键与录音状态,原子地清除 Session 剪辑、走带、Session Record 与
Arrangement Record,并且在宿主重启后仍然有效。

## 录音授权

录音开始预览要求:明确意图、输出安全证据,以及任一通道的精确 armed
目标。应用把精确的先前 Session/Arrangement 录音布尔值、目标身份与输出
安全证据带入映射器;在录音状态改变之前,全部在 Live 的变更线程上复检。
确认丢失是不确定状态,绝不盲目重放。停止使用同样受隔离的操作;独立的
紧急停止会清除两种模式。

## 实时授权

配置了 UDP 端口并不授予常备权限。`realtime.arm` 选择端点、令牌、1–30 秒
TTL、通道集合、可选的发送方端口,以及精确的已发布参数引用。Live 在授予
令牌之前、以及每次排队写入之前,都会原子地比对精确的参数/所有者/轨道/
同级身份,因此遍历索引替换或重新归属会撤销授权。数据包限制为 512 字节、
64/s、突发 16。*已接受*不等于*已应用*。Disarm 会对排队工作进行代际隔离。
参见 [REALTIME_CONTROL.md](REALTIME_CONTROL.md)。

## 音频分析与捕获

公开分析只接受归一化 PCM,绝不接受路径或 URL,只返回有界聚合。它在一次性
的、剥离密钥的 worker 中运行,可通过杀死 worker 取消。调用方 PCM 绝不会
被归因于 Live,除非明确声明了该关系 —— 而声明仍然是未经核实的。

Live 捕获是独立的、仅真实 Live 的能力。预览要求:精确的源剪辑槽位与不同
的空音频槽位、已保存的一次性 Set、停止/未录音/未 armed/未输入监听的
状态、可恢复的路由、一到九秒的时长、显式的
`ephemeral-analysis-and-delete` 同意,以及输出安全。十秒的映射器看门狗、
槽位/轨道/走带停止、桥接关闭钩子、MCP 取消恢复,以及独立的重启后紧急
工具共同约束录音授权。清理只删除精确的自有剪辑,并在私有隔离后解除已
验证 WAV/ASD 的链接;不做任意删除或取证级擦除承诺。参见
[AUDIO_INTELLIGENCE.md](AUDIO_INTELLIGENCE.md)。

## 桥接安全

桥接仅绑定数字回环地址。请求与响应使用规范的 HMAC-SHA256、挑战/桥接
epoch 绑定、正序列与重放检查、有界帧/集合以及截止时间。Socket worker 绝不
触碰 Live 对象;由定期调度的 Control Surface 回调在主线程上排空 Live 工作。
重连会创建新的引用 epoch。关闭会释放订阅、监听器、客户端、worker、排队
回调、实时授权与引用。对于活跃的捕获,它会重新断言精确停止/恢复;但由于
Remote Script 无法解除 PCM 链接,它会把自有的剪辑/路径保留为可见的恢复
残留,而不是销毁那个唯一的恢复身份。

## 真实 Live 证据边界

Fake-Live、模拟器、打包、属性与基准测试结果证明的是受控契约,而不是
Live 行为。受跟踪的证据另行记录了在 macOS Live 12.4.5b8 上、截至 Phase 8
的已安装真实 Live 观察,包括正常清理与故障恢复。它不证明 Windows Live
行为、硬件输出安全、无障碍、签名或公证。

如果可见的 Live 状态与已认证状态或新鲜发现相冲突,请停止客户端、保留
已隐去敏感信息的证据;若自有可发声生命周期处于活跃状态,使用独立的紧急
恢复;并把这种差异视为缺陷。
