# リアルタイムコントロールプレーン

[English](../en/REALTIME_CONTROL.md) · [简体中文](../zh-CN/REALTIME_CONTROL.md) · 日本語

短時間の高レートパラメータ制御のための、オプションの個別アーム式 UDP
エンドポイント —— 明示的に設定されない限り無効で、有効な場合でもフェンス
されています。

本番 Remote Script は、バージョン 2 ブリッジ設定に個別の `realtimePort` が
含まれる場合、ループバック UDP エンドポイントを公開できます:

```json
{
  "bridge": {
    "host": "127.0.0.1",
    "port": 9765,
    "realtimePort": 9766,
    "secretFile": "/absolute/owner-only/bridge.secret",
    "timeoutMs": 5000
  }
}
```

この形状は `ableton-mcp-setup --realtime-port 9766` で生成します。TCP と
UDP リスナーはどちらも設定された数値ループバックアドレスのみにバインドします。
ポート競合は、サイレントにプレーンを無効化するのではなく、起動を失敗させます。

## 権限ライフサイクル

1. `live_realtime_arm_preview` を、1 つ以上の明示的なチャンネル(`udp-json`、
   `osc`、`xy`、`max`)、0〜32 の権威ある公開パラメータ参照の正確な
   許可リスト、1〜30 秒の TTL、オプションの許可送信元ポート、権威ある出力
   安全性の証拠で呼び出します。空の参照リストは緊急停止パケットのみを許可
   します。
2. 期限切れでないトランザクションを `confirmation=apply` と冪等キーで 1 回
   適用します。ホストは最終プレビューの正確なパラメータ、オーナー、トラック、
   順序付き兄弟 ID 記述子を正規 arm リクエストに載せます。Live はトークンを
   作成する前にすべての記述子を原子的に比較します。同じ走査参照での置換は
   拒否されます。アダプターの出所が `real-live` でない場合もアームは拒否
   されます。
3. 結果には、ループバックエンドポイント、予測不可能なベアラートークン、
   有効期限、選択されたチャンネルと正確なパラメータ参照、512 バイトパケット
   制限、64 パケット/秒トークンバケットレート、バーストサイズ 16 が含まれます。
   トークンをログに記録したり永続化したりしないでください。
4. 正のセーフ整数シーケンスを送信します。シーケンス状態は arm ごとに 1 つの
   リプレイドメインです。再アームは以前のトークンとキューされた世代を無効化
   します。
5. `live_realtime_stats` を呼び出して、受理、保留、適用、コールバック失敗、
   ディスパッチ前ドロップ、エンドポイント/トークン/リプレイ/レート/キュー
   ドロップ、未承認ターゲットドロップ、シーケンスギャップ、到着間隔/トランジット
   ジッターを区別します。
6. `confirmation=disarm` で `live_realtime_disarm` を呼び出します。Disarm、
   再アーム、有効期限、ブリッジ切断、メインスレッドデッドライン期限切れは、
   キューされた作業をフェンスします。

`accepted` は Live の有界なメインスレッドキューへの受理を意味し、配信では
ありません。`applied` のみが、スケジュールされたコールバックが完了し、その
公開パラメータ値を同期的に検証したことを確認します。UDP 自体に確認応答は
ありません。

## UDP JSON

すべてのデータグラムは 512 バイト以下の単一の UTF-8 JSON オブジェクトです。
不明なフィールドは拒否されます。

公開パラメータ:

```json
{"token":"<arm token>","seq":1,"channel":"udp-json","op":"parameter.set","ref":"<parameter ref>","value":0.5,"sentAtMs":1700000000000}
```

アトミック XY ペア(いずれかの検証済み書き込みが失敗した場合はベスト
エフォートロールバック):

```json
{"token":"<arm token>","seq":2,"channel":"xy","op":"xy.set","xRef":"<parameter ref>","x":0.4,"yRef":"<parameter ref>","y":0.6,"sentAtMs":1700000000000}
```

Max パッチを含むオペレーター作成のクライアントは、`channel:"max"` で同じ
厳密なオブジェクトをシリアライズできます。これは認証済み拡張パケットラベル
にすぎません: ランタイムステータスは `max` ケイパビリティを通知せず、Max
ハンドシェイクは行われず、`.amxd` デバイスもバンドルされません。パッチは
`udpsend` で返されたループバックエンドポイントに送信できます。既製 Max
デバイスの配布と検証は、別途バージョン管理された拡張のままです。

緊急停止:

```json
{"token":"<arm token>","seq":3,"channel":"udp-json","op":"emergency-stop","sentAtMs":1700000000000}
```

コールバックは正確な新鮮なアクティブターゲットを取得し、Live のスレッドで
ガード付き停止を呼び出します。認証済み TCP の `live_session_emergency_stop`
は、リアルタイムトークンが利用できない場合の独立した回復パスです。

## OSC

OSC バンドルとサポートされていないタイプは拒否されます。サポートされる
メッセージ:

- `/ableton-mcp/parameter` —— 引数 `string token`、`int32|int64 seq`、
  `string ref`、`float|double value`、オプション `double sentAtMs`。
- `/ableton-mcp/xy` —— 引数 `string token`、`int32|int64 seq`、
  `string xRef`、`float|double x`、`string yRef`、`float|double y`、
  オプション `double sentAtMs`。
- `/ableton-mcp/emergency-stop` —— 引数 `string token`、`int32|int64 seq`、
  オプション `double sentAtMs`。

OSC パケットには arm の `osc` チャンネルが必要です。JSON XY パケットには
`xy` が必要です。Max ラベルの JSON パケットには `max` が必要です。緊急停止は
選択された任意のチャンネルを通じて許可されますが、現在のトークン、エンド
ポイント、シーケンス、TTL が依然として必要です。

## Live スレッドと値の安全性

ソケットスレッドは、デコード、認証、アカウント、エンキューのみを行います。
パラメータ解決、境界、有効状態、量子化、書き込み、XY ロールバック、値検証、
再生観測、緊急停止はすべて、Live のスケジュールされた Control Surface
スレッドで実行されます。各書き込みの前に、Live は arm 時に保持された同じ
パラメータ/オーナー/トラック/兄弟記述子を再計算します。トポロジドリフトは
世代を取り消し、キューされた書き込みを拒否します。権威ある境界外の値は、
サイレントにクランプされるのではなく拒否されます。キューは 128 コールバックに
制限され、リアルタイムコールバックには 1 秒のディスパッチ前デッドラインが
あります。

リアルタイムプレーンは、すでに公開されている数値 Live パラメータのみを
書き込みます。デバイスのロード、Browser 項目の選択、ルーティングの変更、
録音の arm、ファイルの書き込み、汎用 Live オブジェクト操作の公開は行いません。

## 回復

- `applyFailures`、`revokedBeforeApply`、`droppedBeforeDispatch`、永続的な
  `pending` 値があった場合は、disarm して再試行前に新鮮なディスカバリを
  実行してください。
- 送信元ポート不一致、不正なトークン/チャンネル、リプレイ、無効なパケット、
  過負荷、フルキューはドロップされカウントされます。自動的に再試行される
  ことはありません。
- Live とブリッジが稼働したまま MCP ホストが再起動した場合、現在のトークンは
  元の有効期限までのみ使用可能です。再接続で延長されません。
- Live またはブリッジが再起動した場合、ソケットは閉じられ、すべてのトークンが
  消えます。
- リアルタイムテスト後は、必ず使い捨て Set で触れたパラメータを復元し、
  停止/非録音状態を確認してください。

macOS の実 Live エビデンスは
[../evidence/phase-7c-realtime-live.json](../evidence/phase-7c-realtime-live.json)
に記録されています。Windows Live エビデンスの代替にはならず、バンドルされた
Max for Live デバイスを証明するものでもありません。
