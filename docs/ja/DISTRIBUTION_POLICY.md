# 配布・署名・公開ポリシー

[English](../en/DISTRIBUTION_POLICY.md) · [简体中文](../zh-CN/DISTRIBUTION_POLICY.md) · 日本語

## 選択されたチャネル

リポジトリで設定されている唯一のリリースチャネルは、`npm pack` で作成する
**正確なローカル npm tarball** です。ソフトウェアと tarball は
[MIT ライセンス](../../LICENSE.md)です。`private: true` は誤って
`npm publish` することを防ぐために維持され、候補は npm、GitHub Releases、
その他のレジストリへ公開されません。インストールは正確なローカルパスと
SHA-256 に紐づきます。SHA はバイト整合性を証明しますが、公開者 ID ではありません。

ローカル成果物は未署名で Apple 公証もなく、ネイティブ macOS/Windows
インストーラーを出荷しません。公開配布、コード署名、公証、商標審査には、
オーナーによる別の判断、承認済み ID、専用リリースゲートが必要です。MIT は
ソフトウェアの利用・再配布権を付与しますが、Ableton の商標権、Ableton による
承認、公開者 ID、プラットフォーム認証を付与または意味しません。

## 成果物許可リスト

tarball に含められるのは次だけです:

- コンパイル済みランタイム JavaScript と宣言(ソースマップとテストを除く)。
- Remote Script、正規操作レジストリ、そのマニフェスト。
- リリースマニフェスト/出所記録とパッケージメタデータ。
- MIT ライセンス。
- 許可されたユーザー、安全、運用、回復、テスト、サポート、配布、実装状況文書。

検証/テストランナー、テストフィクスチャ、依存関係、認証情報、設定、ローカル状態、
ログ、バックアップ、キャプチャメディア、生成エビデンス、保護されたローカル SDK
マテリアルを含めてはいけません。`package:verify` は独立して列挙した許可リスト外の
全パスを拒否し、全マニフェストハッシュを検証します。出所には正確な Node、npm、
TypeScript バージョン、プラットフォーム/アーキテクチャ、ホストイメージ ID、
package-lock/ワークフロー SHA-256、ソースコミット/ダーティ状態、実行可能レシピを
記録します。CI は新規分離クローンと新規 `npm ci` から再パックしてバイト比較し、
実行済みの正確な SHA ジョブだけがエビデンスになります。

## 必須チェックと緊急手順

`Required CI` は安定したマージゲートコンテキストです。正確な候補ビルド、完全な
Node/OS インストール済み候補マトリクス、完全な Python Remote Script マトリクスが
すべて成功した場合だけ成功します。リポジトリに常設の ruleset バイパス主体を
置いてはいけません。

緊急設定変更はリポジトリオーナーだけに予約されます。ルール変更前に、理由、正確な
コミット SHA、失敗/利用不可チェック、リスク、回復計画を記録するインシデント issue
を作成します。その後、一時的にブロック設定だけを変更し、記録済み SHA をマージし、
直ちにルールを復元し、完全な正確候補マトリクスを実行し、バイパス後レビューと結果を
インシデントへ記録します。バイパスは欠落または失敗したエビデンスを成功扱いしません。

## エビデンス境界

Linux はホスト/パッケージ契約プラットフォームのみで Ableton Live を認証しません。
macOS 実 Live エビデンスは明記された Live 12.4.5b8 beta 環境だけを対象とします。
Windows CI はホスト、ACL、ライフサイクル、パッケージ契約を証明できますが、Windows
Live のエビデンスではありません。正確なマトリクスは
[SUPPORT_MATRIX.md](SUPPORT_MATRIX.md) を参照してください。

同じ tarball が再現可能で、マニフェストが正確なクリーン Git コミットを識別し、
その SHA の全ローカル/ホストゲートが成功し、該当する実 Live エビデンスが同じ成果物
ダイジェストを示す場合だけ、候補は現在のローカルチャネルに適格です。過去、
シミュレーター、fake-Live、古いエビデンスは欠落候補セルを埋めません。
