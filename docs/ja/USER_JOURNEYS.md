# ケイパビリティ対応ユーザージャーニー

[English](../en/USER_JOURNEYS.md) · [简体中文](../zh-CN/USER_JOURNEYS.md) · 日本語

5 つのガイド付き作曲ワークフロー —— ビート/ソング作成、高度なドラム、
サウンドデザイン、リファレンス比較、パフォーマンス診断 —— は、読み取り
専用の `plan_user_journey` ツール、`ableton://journeys` リソース、5 つの
MCP プロンプトを通じて公開されます。

ジャーニーは、直接の呼び出し側が使用するのと同じ用途別ガード付きツールの
プランです。プランは変更権限では**ありません**: トランザクショントークン、
確認トークン、冪等キーは含まれません。

## 共有契約

1. `live_status` を呼び出し、報告されたアダプター、エポック、ケイパビリティ、
   操作、レジストリハッシュ、出所に対してプランします。
2. 順序付けられた各テキストステージをアナウンスします。ステータスが色だけで
   表現されることはありません。
3. プレビュー前に新鮮な正確な参照とリビジョンを発見します。
4. 影響、ターゲット、境界、期待される結果、回復ルートを示します。
5. すべての確認ゲートで停止します。あるプレビューの確認が別のステージを
   許可することはありません。
6. ステージで指定された用途別ツールのみを通じて適用します。汎用呼び出しを
   使用したり、自然言語から権限を推測したりしないでください。
7. 新鮮な権威ある事後状態を検証します。キャンセル、タイムアウト、応答喪失、
   矛盾する読み戻しは `uncertain` を意味し、成功ではありません。
8. トランザクション所有のアンドゥ/停止/クリーンアップルートまたは独立した
   緊急権限で回復し、すべての残留物をリストします。

`traits` は 1,000 印刷可能文字に制限され、`bars` は 1〜16、プランはノート
作成を 512 に制限します。許可リストされたリズム、密度、エネルギー、音色、
空間、ダイナミクス、ハーモニー、アレンジメント記述子のみが派生ガイダンスに
入ります。元のリクエストはオペレーターコンテキストのために信頼されていない
ものとしてラベル付けされたままです。ID または完全一致の言語が検出された
場合、**すべての**抽出がブロックされます —— 「Bright」や「Major」のような
偶発的な単語でも —— 呼び出し側は名前なしで特性を再述する必要があります。
ID/コピーテキストはノート、トポロジ、診断ガイダンスに入りません。安全な
特性が認識されない場合、すべてのステージは `blocked-by-intent`、モードは
`intent-clarification-required` となり、実行可能なジャーニーはありません。
プラン ID は、同じ正規化されたリクエストとネゴシエートされた Live 状態に
対して決定論的です。接続状態、アダプター、エポック、出所、レジストリ
ハッシュ、操作セット、ケイパビリティセット、安全な翻訳、入力の変更は、
異なるプランを生成します。

## 1. 編集可能なビートまたはソングセクションの作成

プロンプト: `create_beat_or_song`

このジャーニーは、許可リストされた高レベルのリズム、ハーモニー、
アレンジメント、プロダクション特性を、正確な構造/MIDI プレビューの前に、
有界なテンポ、ロールイベント、グリッド、セクション、ピッチ未設定の
ガイダンスに変換します。Set、空のターゲットスロット、テンポ、デバイス、
停止した再生を発見し、Session 構造と MIDI を別々にプレビューし、各変更に
正確な確認を要求し、別の出力安全性プレビューの後にのみオーディションし、
安定 ID でノートを改訂し、結果を検証またはガード付きでアンドゥします。
Arrangement、改訂、オーディションステージは、正確なケイパビリティと操作が
ネゴシエートされている場合にのみ `planned` とマークされます。それ以外の
場合は、非変更フォールバック付きで `unavailable` です。

必要な Session/MIDI ケイパビリティが欠落している場合、サーバーは編集可能な
ノート/構造プランを返し、利用できない各操作を名前で示します。Live が結果を
含んでいる、または再生したと主張することはありません。

## 2. 高度なドラムのシーケンス

プロンプト: `sequence_advanced_drums`

このジャーニーは、マッピングを推測する代わりに Drum Rack パッドピッチを
発見します。それらのフィールドが通知されている場合、有界なベロシティ、
分数タイミング、確率、ベロシティ偏差、リリースベロシティをプレビューおよび
検証できます。サポートされていない MPE、グルーヴ抽出、ノートごとの表現、
モジュレーションは明示的に利用不可のままです。通常のタイミングやベロシティが
それらの機能として再ラベル付けされることはありません。オーディションと
回復は、正確な所有クリップのみを対象とします。

## 3. 利用可能な所有/ネイティブデバイスを使用したサウンドデザイン

プロンプト: `design_owned_sound`

このジャーニーはセマンティックなトポロジ/コントロール方向を導出し、安定した
結果 ID で Browser を検索し、選択された 1 つの結果のロードをプレビューします。
デバイスのない Set でも Browser ロードを通知できるため、`devices`、
`parameters`、`device.parameter.set` はロード後に再ネゴシエートされます。
クライアントは、古いプランが変更されたと想定するのではなく、その接続スコープの
ネゴシエーション後に再計画する必要があります。パラメータ変更は、正確な公開
数値コントロールと境界を使用します。Live パラメータまたはプリセット API を
公開しないプラグインには、手動の指示のみが提供されます。デバイスの存在は
因果的なオーディオ証明として主張されません。

## 4. ユーザー提供のリファレンスとの比較

プロンプト: `compare_reference_mix`

Live が切断されていても、ローカル規格解析は利用可能です。このジャーニーは、
明示的な権利と同意の関係を持つ呼び出し側提供/生成 PCM を受け入れ、有界な
使い捨てワーカーを実行し、ITU-R BS.1770-5/EBU R128 ラウドネスとトゥルー
ピーク、アライメント信頼度、ダイナミクス、スペクトル、トランジェント集約を
報告し、生 PCM を返しません。新鮮な Live コンテキストまたはガード付き
Session Resampling キャプチャはオプションです。観測されたトポロジ、測定値、
仮説は分離されたままです。単なるデバイスやルーティングの存在から因果の主張は
されません。

自動アライメントの曖昧さは、拒否または文書化された手動/無効フォールバックに
なります。提案されたミキサー実験は、新鮮な同スコープ測定による 1 つの可逆的な
仮説であり、マスタリングの確実性ではありません。

## 5. ミックス、録音、パフォーマンスセットアップの診断

プロンプト: `diagnose_performance_setup`

読み取り専用の最初のパスは、再生、arm、モニタリング、ルーティング、ミキサー、
デバイス、オートメーション、プロジェクト、サブスクリプション、リアルタイム
回復状態を集約します。変更を提案する前に、正確な参照の所見をランク付けします。
フィードバックを起こしやすいルーティング、録音、可聴再生、リアルタイムアームは、
個別のプレビューと確認を使用します。リアルタイムレポートは、受理された
パケットと適用された変更を区別し、有界なトークン有効期限/ディスアームと
独立した TCP 緊急停止を要求します。不明なレイテンシは不明のままです。
サーバーは UDP の可用性だけで低レイテンシパスを主張しません。

ルーティング、ミキサー、トランスポート、録音、停止権限が利用できない場合、
フォールバックは読み取り専用チェックリストです。arm、モニター、録音、ルート、
再生、準備完了の主張は行いません。

## 権利対応の意図翻訳

`traits` 内のアーティスト、レコード、曲、人物、完全一致の文言は、
`untrustedOriginalRequest` としてのみ保持され、派生クリエイティブガイダンス
から除外されます。名前に語彙が含まれる可能性があるため、検出は抽出全体を
ブロックします。ユーザーは ID/コピーの文言なしで、認識された許可リストの
高レベル記述子を再提出する必要があります。そのようなリクエストは、偽の翻訳
ではなく、明確化の要件を生成します。プランは、保護されたソースマテリアルへ
のアクセスを要求または主張せず、正確な複製を約束せず、法的クリアランスを
断言しません。リファレンス PCM は、呼び出し側が使用を許可されている関係の下で
提供または生成される必要があります。サーバーは著作権所有権やライセンスを
判断できません。

## 進行と回復の言語

すべてのプランは、この順序付けられた実行語彙を提供します:

`discovering` → `planned` → `awaiting_confirmation` → `applying` →
`verifying` → `completed`

返されるステージステータスは明示的にプランニングテンプレート(`planned`
または `unavailable`)であり、実行の真実ではありません。クライアント/エージェントは
実際の用途別ツール結果からランタイム進行を導出し、終端パスは代わりに
`recovered` または `uncertain` になることがあります。終端結果は、該当する
残留再生、録音、ルーティング、一時メディア、リアルタイム権限、作成オブジェクト
状態を述べなければなりません。クライアントは詳細の前にステージタイトルを
アナウンスし、初心者向けサマリーを正確な参照、エポック、リビジョン、レジストリ
ハッシュから分離する必要があります。

## アクセシビリティの範囲と既知の制限

出荷される製品は JSON-RPC/MCP stdio サービスと CLI であり、グラフィカル
エディターではありません。そのアクセシブルな契約はテキストファーストです:

- セマンティックなツール、リソース、プロンプト、ステージ、影響、確認、
  ステータス名
- 配列とプロンプトテキストの決定論的な読み順
- マウスのみのサーバー指示や色のみの結果がない
- 波形、スペクトル、メーター、その他の視覚的サマリーにテキスト代替が必要
- クライアントアナウンスとキャンセルに適した有界な出力

サーバー所有のフォーカスカーソル、パネル、キャンバス、キーボードショートカット
がないため、フォーカス管理とコントラストは stdio 境界では適用されません。
ホストは MCP クライアント、ターミナル、Ableton Live のアクセシビリティ動作を
制御**しません**。VoiceOver/Narrator サポート、フォーカス順序、キーバインド、
Live プラグインウィンドウのアクセシビリティは、それらの製品とバージョンに
依存します。支援技術を必要とするオペレーターは、選択したクライアントと Live
バージョンを検証する必要があります。アクセシブルでないプラグイン UI は、
主張されたケイパビリティではなく、手動の制限のままです。
