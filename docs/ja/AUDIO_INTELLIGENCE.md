# オーディオインテリジェンスと同意ベースの Live キャプチャ

[English](../en/AUDIO_INTELLIGENCE.md) · [简体中文](../zh-CN/AUDIO_INTELLIGENCE.md) · 日本語

オーディオツールチェーン: 呼び出し側提供の PCM 解析、リファレンス比較、
Live コンテキスト診断、そして実際の認証済みブリッジがある場合のみの
同意ベース Session Resampling キャプチャ。

## ケイパビリティの境界

オーディオインテリジェンスには 3 つの異なるソースがあり、混同してはいけません:

1. `audio_analyze` は呼び出し側提供のインターリーブされたリトルエンディアン
   float32 PCM を受け付けます。その PCM を Live に帰属させることはありません。
2. `audio_compare_reference` は 2 つの呼び出し側提供 PCM ソースを受け付けます。
   リサンプリング、アライメント、レベル比較を行い、集約のみを返します。
3. `live_audio_capture_preview/apply` は、認証済みの `real-live` Remote
   Script がすべての `audio.capture.*` 操作と `audio.capture.resampling` を
   ネゴシエートした場合にのみ利用可能です。Live の Resampling 入力を 1 つの
   正確な空のオーディオ Session スロットに録音し、結果の有界な WAV を解析し、
   トランザクション所有の Live クリップと生メディアの両方を削除します。

Remote Script は PCM を公開しません。3 番目のワークフローは用途別の Live
録音ライフサイクルであり、捏造されたマッパータップでも Max for Live の
主張でもありません。

## 規格解析

`pcm-analysis/v3` は `standardsAudio` と、明示的に非推奨の互換値である
`loudness.rms-derived-proxy` を保持します。また、正規化されたソースサンプルが
フルスケール境界に達した場合の `clipping` と、帯域制限された比較用再構成に
よって 0 dBFS を超えた値の `reconstructedOvers` を区別します。再構成オーバーは
ソースのクリッピングを証明しません。デリバリーやマスタリングの決定には、
互換プロキシではなく `standardsAudio` を使用してください。

規格結果が識別するもの:

- ITU-R BS.1770-5 プログラムラウドネス
- EBU R128 運用セマンティクス
- EBU Tech 3341 モーメンタリ(400 ms)およびショートターム(3 s)測定
- EBU Tech 3342 ラウドネスレンジ(−70 LUFS 絶対ゲート、−20 LU 相対ゲート、
  文書化された R-7 パーセンタイル)
- 400 ms 統合ブロック(100 ms ケイデンス)、−70 LUFS 絶対ゲーティング、
  −10 LU 相対ゲーティング
- セマンティックチャンネルラベルとウェイト。モノとステレオは推測されます。
  より大きなレイアウトには明示的な `M`、`L`、`R`、`C`、`Ls`、`Rs`、
  `LFE` ラベルが必要です。LFE は除外され、サラウンドは従来の 1.41 ウェイトを
  使用します
- サンプルピークとトゥルーピークは別々に

48 kHz では、トゥルーピークは BS.1770-5 Annex 2 で公開されている order-48
4 相 FIR 係数を使用します。44.1 kHz では、有界な 64 タップ Blackman-sinc
による 48 kHz への変換が Annex 2 インターポレーターの前に行われます。その他の
レートは、サイレントにサンプルピークを代用するのではなく、トゥルーピークを
利用不可として返します。プログラムラウドネスは、レート由来の K ウェイティング
フィルターを通じて 8〜384 kHz の整数レートをサポートします。48 kHz では正確な
公開係数が使用されます。

無音、不十分な長さ、不明なマルチチャンネルレイアウト、トゥルーピーク作業境界
を超える入力は、NaN、無限大、捏造された測定値ではなく、明示的な利用不可/null
値を返します。モーメンタリおよびショートタームシリーズは非可逆で 128 ポイントに
制限されます。ゲーティングは引き続きすべての有界ウィンドウを使用します。

独立した検証には、生成された再配布可能な PCM と FFmpeg の `ebur128` 実装を
使用します。サードパーティのテストオーディオはコミットされません。実行:

```sh
cd apps/mcp-server
npm run audio:oracle
```

追跡されたオラクルレポートは
[../evidence/phase-8-audio-oracle.json](../evidence/phase-8-audio-oracle.json)
です。宣言された比較トレランスは、48 kHz で 0.1 LU/dB、検証済み 44.1 kHz
変換で 0.15 dBTP です。プライマリ仕様が権威であり続け、FFmpeg は独立した
実装チェックであり、規範的な定義ではありません。

## 分離解析とキャンセル

本番 MCP 解析はホストイベントループで同期的に実行されません。
`AnalysisRunner` は使い捨ての Node 子プロセスを起動します:

- 最大 2 つのアクティブジョブと 4 つのキューされたジョブ
- 512 MiB V8 ヒープ上限
- 30 秒のウォールデッドライン
- 2 MiB stdout と 16 KiB stderr の制限
- 64 MiB ワーカーリクエスト制限
- アプリケーションシークレットを継承しない
- MCP キャンセルまたはタイムアウト時の即時子終了

JSON 集約結果のみが戻ってきます。ワーカーは URL やファイルシステムパスを
受け付けません。パブリックツールは正規化された PCM のみを受け付けます。
Live キャプチャファイルパスは、検証済みキャプチャライフサイクルの内部です。

## リファレンス比較

`audio_compare_reference` は、32〜96 kHz モノ/ステレオソース(固定 32 タップ
カーネルの検証範囲)、ペア全体で最大 400 万入力サンプル、ソースあたり最大
30 秒、最大 10 秒のアライメントラグをサポートします。以下を行います:

1. 決定論的な 32 タップ Blackman ウィンドウ sinc リサンプラーで各ソースを
   48 kHz に変換
2. 100 Hz 粗エンベロープ検索の後、1 kHz、±10 ms の精密検索を実行し、
   無制限の二次精密相関を回避
3. 弱い、無音の、または競合する自動マッチを拒否。手動および無効アライメント
   モードは明示的
4. アライメントが信頼される場合は等しいオーバーラップのみを解析。自動
   アライメントが利用できない場合は、個別のソースごとの解析を保持しますが、
   オーバーラップをゼロに設定し、すべての比較デルタ/レベルマッチ助言を
   利用不可に設定
5. 両方のソースが適格な場合、BS.1770 統合レベル差と有界な ±24 dB アドバイザリ
   マッチ値を報告
6. ラウドネス、トゥルー/サンプルピーク、RMS、クレスト、ダイナミックレンジ、
   スペクトル、トランジェント密度のデルタを、アライン済み PCM を返さずに報告

`reference-analysis/v2` はソース領域の境界カウントを
`resampling.*.sourceClipping` として報告します。実際に 48 kHz へ変換された
ソースでは、ネストされた解析が 0 dBFS を超える再構成値を
`reconstructedOvers` として分離し、ソースの `clipping` と誤表示しません。
有損振幅ヒストグラムは有界な再構成レンジに合わせてスケーリングされるため、
1 を超える値がすべて最終ビンへ潰れることもありません。

リサンプリングはタイムストレッチやテンポマッチングではありません。提案された
レベルマッチはオーディオを変更しません。

## シグナルチェーン連携診断

`audio_diagnose_live_context` は呼び出し側 PCM 測定値を 1 つの新鮮なトラック
スナップショットに関連付けますが、その関係を呼び出し側宣言かつ未検証として
マークします。マッパー所有のキャプチャ解析は、その関係を
`verified-by-capture-lifecycle` としてマークします。診断には、正確な Set、
トラック、ミキサー/ルーティング参照、順序付きデバイス参照、有界な公開
パラメータ値が含まれます。

所見は測定値と仮説を区別します。デバイスの存在が因果と呼ばれることはありません。
欠落しているレイテンシ、サイドチェーントポロジ、非表示パラメータ、ゲイン
リダクション、正確なデバイス内タップ位置は明示的に名前が付けられます。
ミキサープレビューの提案(存在する場合)は、明示的な確認と同スコープの
再キャプチャを必要とする可逆的な正規化コントロール実験であり、約束された
dB 補正ではありません。`causality.claimed` は常に false です。

## Live Resampling ライフサイクル

### プレビュー

`live_audio_capture_preview` には以下が必要です:

- `real-live` の出所と 6 つすべての正規キャプチャ操作
- 正確な使い捨て Set 名
- 1 つの正確なソース Session クリップスロットと、異なる正確な空のオーディオ
  スロット
- 復元可能で現在使用可能なデスティネーション入力ルート
- 停止したトランスポート、Session および Arrangement 録音オフ、アクティブ
  ターゲットなし、すべてのトラックが unarmed、入力モニタートラックなし
- 1〜9 秒の要求時間
- `consent=ephemeral-analysis-and-delete`
- 新鮮な非シミュレーター出力安全性の証拠

Live の古い `Ext. In` ルートが選択できなくなっている場合、オペレーターは
プレビュー前に `No Input` などの利用可能な安全なルートを選択する必要が
あります。これは明示的な通常のルーティングトランザクションであり、隠れた
キャプチャの副作用ではありません。

### 適用とウォッチドッグ

適用には、予測不可能なプレビュー確認と冪等キーが必要です。Live のメイン
スレッドで、`audio.capture.start` はソース/デスティネーショントラック/スロット
オブジェクト ID と完全なフェンスを再チェックし、デスティネーショントラックに
一時的に未公開のランダムな所有権タグを付与し、その正確なデスティネーションで
Resampling、モニタリングオフ、arm を設定し、起動量子化を一時的に即時に設定し、
正確にデスティネーションとソーススロットを発射します。非同期に出現する
クリップは、Live が録音中としてマークし、その名前がプライベートタグを持つ
場合にのみ所有されます。その後、デスティネーション名と起動量子化が復元されます。
開始を自動的に再試行することはありません。

マッパーウォッチドッグのハード上限は 10 秒です。ホスト停止、キャンセル、
ウォッチドッグ期限切れ、緊急停止、ブリッジシャットダウンは、正確なソースと
デスティネーションスロット/トラックを停止し、トランスポートと録音を停止し、
位置、名前、ルーティング、arm、モニタリングを復元し、再生または所有クリップが
録音中である間、停止を再主張します。ブリッジ/Live の切断はメディア自体を
アンリンクできません: 唯一の回復 ID を削除する代わりに、所有クリップ/パスを
可視のホストまたは手動クリーンアップ残留物として意図的に保持します。外部編集は
サイレントに上書きされるのではなく、残留状態として報告されます。

### 取得と切断

保存されたプロジェクトディレクトリまたは従来の `User Library/Samples/Recorded`
境界内の、新鮮な通常の非シンボリックリンク単一リンク WAV のみが受け入れられます。
ファイルは最大 32 MiB、12 秒、2 チャンネルで、サポートされている PCM16/24/32
または float32 パッキングを使用する必要があります。読み取り中、ID、サイズ、
mtime、SHA-256 がフェンスされます。公開応答には、フォーマット/レート/チャンネル/
長さの要約が含まれますが、生パス、ダイジェスト、PCM、トークン、確認は含まれません。

分離解析後、ホストは no-follow ディスクリプタセマンティクスで WAV/ASD を開き、
デバイス/inode/リンク数/ダイジェスト ID を再チェックし、検証済み inode を
ランダムなオーナー専用同一ファイルシステム隔離に移動し、切り詰めてアンリンク
します。生クリーンアップが成功した後でのみ、`audio.capture.cleanup` は正確な
トランザクション所有 Live クリップを削除します。その後、解析/クリーンアップ中に
作成された `.asd` の有界なポストクリップ安定不在スイープを実行し、メディアパス
と隔離残留物の両方が残っていないことを検証します。この順序は、ホスト障害を
またいで Live のパス/クリップ回復 ID を保持します。「削除」とは検証済み
アンリンクを意味します。SSD またはコピーオンライトストレージでのフォレンジック
消去の主張ではありません。最終読み戻しは、停止/非録音再生、復元された
デスティネーション状態、空のスロット、マッパー状態 `cleaned`、残留生ファイル
なしを示さなければなりません。

## 独立した回復

`live_audio_capture_status` はマッパートークンとメディアパスを秘匿します。
`live_audio_capture_emergency_stop` には `confirmation=emergency-stop-and-clean`
と新鮮に観測された正確なキャプチャ/ソース/デスティネーション ID が必要です。
ホスト再起動後も機能し、認証済みブリッジを介してマッパー保持の回復権限を取得し、
キャプチャを停止し、生ファイルを安全に再検証/隔離/アンリンクしてから、所有
クリップを削除します。パス、ID、ファイルフォーマット、クリーンアップが証明
できない場合は、不確定な残留状態を返し、任意のファイルを削除しません。

チェックインされたオペレーターランナーは
`apps/mcp-server/scripts/verify-phase8-live.mjs`(`npm run audio:live-verify`)
です。必要なレシート、クリーンな Git SHA、正確な成果物とレジストリダイジェスト、
インストール済みバイト検証、新鮮な出力安全性入力は [TESTING.md](TESTING.md) に
文書化されています。実 Live パッケージエビデンス(通常キャプチャ、制御された
再キャプチャ、実証された MCP 応答抑制、ホスト死亡後のマッパーウォッチドッグ、
独立した回復、ゼロ生/隔離残留物を含む)は
[../evidence/phase-8-audio-live.json](../evidence/phase-8-audio-live.json) で
追跡されています。

## 明示的な制限

- `.amxd` デバイス、ストリーミング Max for Live タップ、プラグイン UI メーター、
  任意パス、URL フェッチ、タイムストレッチ、マスタリンググレード、自動
  コンプライアンス判定は主張されません。
- トゥルーピークは現在 44.1 kHz と 48 kHz でのみ検証されています。
- 従来のセマンティックチャンネルラベルがサポートされています。イマーシブ/オブジェクト
  レイアウトは利用できません。
- Live キャプチャは WAV のみで、保存された Set と復元可能なルートが必要です。
- 生アンリンクはフォレンジックメディア消去を約束できません。オーナーアカウントが
  ローカル信頼境界です: すでに同じユーザーとして実行されている悪意のあるプロセスは
  オーナー専用ブリッジシークレットを読み取ることができ、脅威モデル外です。
  no-follow、リンク数、inode、ダイジェスト、プライベート隔離チェックは、その
  境界内での偶発的/古い/パス置換の危険から防御します。
- 実 Live エビデンスは macOS Live 12.4.5b8 のエビデンスであり、Windows Live の
  証明ではありません。
