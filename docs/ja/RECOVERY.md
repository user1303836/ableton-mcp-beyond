# 回復手順

[English](../en/RECOVERY.md) · [简体中文](../zh-CN/RECOVERY.md) · 日本語

何かが途中で失敗したときの対処法。黄金律: **不確定な状態は新しい権限で
再試行しない** —— 不変のエポックで元のトランザクションを照合するか、
新鮮な権威ある状態から手動で回復してください。

## プロトコルと入力エラー

リクエストを修正し、新鮮なリクエスト識別子を使用してください。不正または
超大の入力については、拒否されたフレームを破棄し、秘匿された stderr 診断
のみを確認してください。認証、フレーミング、シーケンシング、応答相関が
信頼できなくなった場合は、プロセスを停止して再起動してください。その
ストリームを継続しないでください。

## 設定とライフサイクルのエラー

設定パスが明示的で、通常ファイルで、非シンボリックリンクで、オーナー管理
であること、設定がバージョン 1 または 2 であること、ブリッジホストが正確な
ループバックであること、インストールプリフライトでポートが個別/空きである
こと、別のシークレットが決定的なオーナー専用権限を持つことを確認して
ください。シークレットをコマンドラインに置かないでください。

レシート駆動ライフサイクルの障害では、Live を停止し、
`install-receipt.json`、`lifecycle-journal.json`、管理対象ハッシュ、
隔離を確認してから再試行してください。失敗したインストールは新しく作成
されたシークレット/設定/ブリッジ状態を削除します。失敗したアップグレードは
古い設定/ブリッジを復元し、レシート世代は変更されません。保持された
ファイル、ACL エラー、シンボリックリンク/ジャンクション、占有ポート、
中断されたリネームは成功ではありません。ハンドルを解放するか権限を修正し、
status と repair を使用してください。修復はドリフトを隔離に保持し、欠落
したシークレットを捏造することを拒否します。ロールバックは正確なレシート
紐付けの前世代のみを使用します。アンインストールはコミット前に所有パスを
ステージし、コミットが失敗した場合はそれらを復元し、レシート所有の
ロールバック世代を退役させ、ドリフトを隔離し、レシート所有のパージが
明示的でない限りシークレットを保持します。コミット後の削除がブロック
された場合、レシートは `pendingCleanup` を保持します。ハンドルを解放して
正確なアンインストールコマンドを繰り返してください。`preserved` パスは
オペレーターのコンテンツであり、再試行で削除されることはありません。
ロールバックが通知されている間は、バックアップを手動で置換または削除
しないでください。[DELIVERY.md](DELIVERY.md) を参照してください。

## アダプターの不確実性

認証失敗、レジストリ不一致、応答 MAC 失敗、リプレイ、シーケンスエラー、
不正な応答、タイムアウト、キャンセル、切断、応答喪失は、結果が**不明**
であることを意味します。新しい変更権限を発行しないでください。実行中の
ホストは、同じ認証済みブリッジと不変の Live エポックにのみ再接続し、元の
トランザクション、確認、正規引数、冪等キーを再利用し、Remote Script 台帳の
結果を取得し、新鮮な事後状態を検証できます。これは照合であり、新しい
リプレイではありません。ブリッジまたは Live エポックの変更はフェイル
クローズし、手動の権威ある回復が必要です。

非表示のクリーンアップトークンは、同じアダプターインスタンスが実行する
トランスポート再接続を存続しますが、意図的にディスクに永続化されず、
代替ホストプロセスに譲渡できません。ホストのトランザクションレコードも
同様にメモリ内です: プロセス置換後、自動破壊的クリーンアップは利用できず、
正確な手動読み戻し/回復が必要です。独立して許可された緊急停止のみが再起動を
存続します。

キャンセルされた stdio リクエストには、キャンセル応答は発行されません。
ハンドラーディスパッチ前のキャンセルは作業を防ぐことがありますが、
ディスパッチ後のキャンセルは Live の作業を元に戻しません。後者は不確定と
して扱い、さらなる変更の前に新鮮な読み戻しを行ってください。

## トランザクション回復

プレビューの有効期限切れ、古いエポック、古いリビジョン、無効な親、占有
された Session スロット、重複する構造名、ロケーター衝突、サポート外または
無効なパラメータ、範囲外または不正に量子化された値、外部編集は、新鮮な
権威あるディスカバリと新しいプレビューを要求します。応答喪失の apply、
undo、補償は回復保護されたままとなり、不変のブリッジ/Live エポックで元の
冪等キーのみを受け付けます。マルチステップ構造、ロケーター、キャプチャ、
MIDI、オートメーションの回復は、保持された正確なステップ引数をリプレイし、
完了済みのステップを検証し、トランザクション所有の残りのみを再開します。
異なるキーはフェイルクローズします。デバイスパラメータについては、復元前に
同じデバイス子関係と正確な以前/適用された値を検証してください。

デバイスと Arrangement クリップの恣意削除は、削除された状態を再構成できない
ため利用できません。クリーンアップは、作成フィンガープリントと現在の階層が
一致する正確なトランザクション作成 ID のみを削除します。変更または置換された
所有オブジェクトは拒否されます。権威ある手動回復の後、
`live_recovery_finalize` は `confirmation=finalize-recovery-record`、宣言
された解決、有界な出所/スコープの証拠を必要とします。アクティブな可聴/録音/
リアルタイム作業を拒否し、ホスト容量を解放する前に Remote Script のリプレイ
権限を退役させます。

シーンオーディションでは、まず新鮮な認証済み再生ディスカバリを実行して
ください。接続エポック、Set 名、シーンリビジョン、録音状態、arm/モニター
状態、出力証拠、アクティブターゲットがトランザクションと異なる場合、ガード
付き停止は拒否され、オペレーターは Set を手動で検査する必要があります。
同エポックの応答喪失は元の apply または stop キーのみを受け付けます。新しい
キーを代用しないでください。独立した新鮮な観測による
`live_session_emergency_stop` はホスト再起動後も利用可能です。

録音の応答喪失は常に不確定です。両方の録音モード、正確なデスティネーション
トラック、再生ターゲットを再読してください。適用された可能性のある開始は、
不変のエポックで元のトランザクション/キーを通じてのみ照合してください。
回復として 2 回目の開始をプレビューまたはディスパッチしないでください。
いずれかの録音モードがアクティブなままの場合は、正確な新鮮な再生ターゲット
と必須の `expectedRecording` 値(`session`、`arrangement`、`both`。両方の
新鮮なフラグが false の場合のみ `stopped`)で `live_session_emergency_stop`
を呼び出します。そのマッパー側フェンスは録音状態も検証し、
`recordingStopped=true` を報告する前に Session Record と Arrangement Record
をクリアします。

## リアルタイム回復

`live_realtime_stats` がコールバック失敗、取り消された作業、ディスパッチ前
ドロップ、永続的な保留作業を報告したら、すぐに disarm してください。Disarm、
有効期限、再アーム、ブリッジ切断は、開始されていないコールバックを世代
フェンスします。UDP 送信成功や `accepted` カウンターから配信を推測しないで
ください。`applied` のみが完了した検証済み Live スレッド書き込みを報告します。
触れたパラメータを新鮮な権威ある参照で復元し、停止/非録音状態を確認して
ください。リアルタイムトークンがない、またはデータプレーンが疑わしい場合は、
TCP の `live_session_emergency_stop` が独立した回復パスです。
[REALTIME_CONTROL.md](REALTIME_CONTROL.md) を参照してください。

## オーディオキャプチャ回復

MCP キャンセル、ホスト終了、トランスポートの沈黙からクリーンアップを推測
しないでください。新しいパッケージホストを開き、`live_audio_capture_status`
を呼び出してください。このツールはリカバリートークンと生パスを秘匿しますが、
正確なキャプチャ/ソース/デスティネーション ID、アクティブ/状態、ウォッチドッグ
停止、ファイル可用性、再生停止を報告します。

状態が `cleaned` でない場合は、`confirmation=emergency-stop-and-clean` と
新鮮に観測された正確な ID で `live_audio_capture_emergency_stop` を呼び出して
ください。これは独立して、正確なソース/デスティネーションスロットとトラック、
トランスポート、録音を停止し、量子化発射レースをまたいで停止を再主張し、
外部編集が検出されない限り所有するルート/arm/モニター/位置状態を復元し、
保存されたプロジェクト/ユーザーライブラリ境界内の正確な新鮮な WAV/`.asd`
inode を検証、プライベート隔離、切り詰め、アンリンクし、生クリーンアップ後に
正確なマッパー所有キャプチャクリップのみを削除します。

成功には `cleanup.safe=true`、空の残留物、最終状態 `cleaned`、
`playbackStopped=true`、WAV/ASD ファイルなしが必要です。ルートが外部で
変更された、メディアが境界外、Set パスが利用不可、ファイル ID が変更された、
フォーマットが未サポート、アンリンクが失敗した場合は、すべての新しいキャプチャ
試行を停止し、指定された残留物を手動で解決してください。任意のパスを削除
しないでください。フォレンジック消去を主張しないでください。
[AUDIO_INTELLIGENCE.md](AUDIO_INTELLIGENCE.md) を参照してください。

## 再起動

1. スーパーバイザーを停止し、秘匿された診断を保持します。
2. 生成されたアーカイブや認証情報ファイルが収集されていないことを確認します。
3. stdout と stderr を分離して `dist/src/cli.js` を再起動します。
4. `2025-11-25` で初期化し、`notifications/initialized` を送信します。
5. 新鮮なステータスとディスカバリを取得し、再度プレビューし、新しい有界な
   冪等キーを使用します。

実際の Live が関係する場合は、続行前に Set を停止して目視で検査してください。
リポジトリで制御されたエビデンスは、その検査や復元の証明に代わるものでは
ありません。
