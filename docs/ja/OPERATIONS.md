# 運用ガイド

[English](../en/OPERATIONS.md) · [简体中文](../zh-CN/OPERATIONS.md) · 日本語

日常使用における実行、監視、シャットダウン。障害後の不確定な状態については
[RECOVERY.md](RECOVERY.md) を参照してください。

stdout と stderr を分離したスーパーバイザー下でホストを実行してください。

## 起動と監視

```sh
cd apps/mcp-server
npm ci
npm run build
node dist/src/cli.js --config /absolute/path/bridge-config.json
```

初期化後に `server_status`、`capabilities`、`live_status` を使用します。有効な
`live_status` は `ableton-live/v1`、接続された `remote-script` アダプター、
非 null のエポック、期待されるレジストリハッシュ、ネゴシエートされた操作を
識別します。`live_snapshot` と有界なディスカバリがアクティブな読み取り専用
チェックを提供します。オーディションの前に、正確な Set、シーン、ターゲット
トラック/スロット、Session 再生状態を発見してください。診断によるディスカバリは
起動の許可ではありません。

診断は引数なし、または正確に 1 つの `--config PATH` を受け付けます:

```sh
npm run diagnostics -- --config /absolute/path/bridge-config.json
```

診断は、ローカルのホスト/パッケージ/設定の準備状態と、認証済み到達可能性、
ディスカバリ到達可能性、レジストリハッシュ、エポック、プロトコル、
`liveConnected` を分離します。ファイル、プロセス、オープンポート、
インストール済みパッケージ、シミュレーター、fake-Live の結果は、実際の Live
接続を確立できません。

Remote Script のファイル診断は独立したデフォルト無効のローカル契約です。
ライフサイクルインストール時の `--enable-bridge-diagnostics` でのみ設定でき、
予測可能な一時ファイルを作っても有効になりません。宛先は選択した状態
ディレクトリ内のオーナー専用・非リンク `bridge-diagnostics.log` です。非ブロック
64 レコードキューがデーモンライターへ渡し、各レコードは最大 512 バイト、
ファイルは 256 KiB を超える前にリセットされます。時刻、固定イベントコード、
粗い許可済みカテゴリ、有界なドロップ数だけを記録し、例外メッセージ/トレース、
リクエスト、シークレット/MAC/トークン、Set/プロジェクト/オブジェクト名、Browser
クエリ、PCM、メディアパスは記録しません。キュー圧力ではドロップし、リンク/
パスドリフト、満杯/書き込み失敗、不安全な記述子では運用エラーを変えず診断だけを
無効にします。

## 制限とシャットダウン

ホストの制限: JSON-RPC フレーム 64 MiB、リモートフレーム 1 MiB、リモート
保留作業 64 リクエスト、追跡リクエスト識別子 4096、ツール呼び出しはローリング
1 分間に 120 回。Stdio は有界な並行処理(デフォルト 16、最大 64)を許可し、
設定された並行性の 4 倍でバックプレッシャーをかけ、応答順序を保持し、
ディスパッチ後のキャンセルを撤回不可として扱います。PCM 解析は 10,000,000
サンプル / 600 秒に制限されます。リファレンス比較は 4,000,000 サンプル /
ソースあたり 30 秒 / 10 秒ラグに制限されます。DSP は最大 2 つのアクティブと
4 つのキューされた使い捨てワーカーで実行され、512 MiB ヒープ、30 秒の
ウォール制限、64 MiB リクエスト、2 MiB stdout、16 KiB stderr の制限があります。
Live キャプチャは 1 つのマッパー所有ライフサイクル、1〜9 秒の要求時間、
10 秒のウォッチドッグ、32 MiB WAV、12 秒、2 チャンネルに制限されます。

正常終了は stdin を閉じます。EOF、シグナル、初期化失敗、キャンセル、出力
失敗、タイムアウト、切断時には、ホストはアダプターを閉じて保留作業を精算します。
新しいエポックを取得するには再初期化してください。シーンオーディションの
切断、タイムアウト、応答喪失は不確定な再生状態であり、安全な再試行条件では
ありません。

## リアルタイム操作

設定された `realtimePort` はそれ自体では権限を付与しません。
`live_realtime_arm_preview`/`apply` を使用し、返されたトークンをログに
出力せず、`live_realtime_stats` を確認し、必ず `live_realtime_disarm` を
呼び出してください。受理された UDP パケットと適用された Live スレッド
コールバックは別のカウンターです。エンドポイント、リプレイ、レート、キュー、
有効期限、世代フェンスによるドロップは明示的です。パケット形式、制限、
OSC/XY/Max 拡張セマンティクス、回復については
[REALTIME_CONTROL.md](REALTIME_CONTROL.md) を参照してください。

## ドメインと拡張の境界

リネーム、Browser ロード、オーディオクリップの変更は、用途別の
preview/apply/undo トランザクションを使用します。汎用の認証済み `invoke` は
ユーザー向けの変更権限ではありません。Browser ロードは新鮮で正確な
`browser.inspect` デバイス ID を必要とします。オーディオ編集はクリップごとに
フィールドネゴシエートされます。ワープマーカーの読み戻しはマーカー編集権限を
付与しません。サブスクリプションは、実際のプロデューサーがあるイベントタイプ
(`transport`、`object`、プロトコル `reset`)のみをネゴシエートします。
未配信の隣接イベントの統合はシーケンスを保持します。実際のキューオーバー
フローやエポック変更は `reset` を発行し、リセットまたはシーケンスギャップは
新鮮なスナップショットを要求します。

`ableton://max-extension` は、Max デバイスがバンドルされていないことを正直に
報告します。正規の `project.new/open/save/save-as/collect/export/bounce`
識別子は将来のアダプター契約のために予約されていますが、現在のアダプターは
それらを通知も実行もしません。ローカルの `project.info` とレシート紐付けの
`.als` バックアップが唯一のプロジェクト操作です。

## 録音操作

Session と Arrangement の録音開始はどちらも、正確な armed デスティネーション、
明示的な意図、出力安全性の証拠を必要とします。マッパーは両方の以前の録音
ブール値と、デスティネーションおよび安全権限を原子的に再チェックします。
不確定後に 2 回目の開始や新しいキーを発行しないでください: 不変のブリッジ/
Live エポックでは、元のトランザクションとキーのみを照合します。それ以外の
場合は、新鮮な再生を発見し、次に正確なアクティブターゲットと
`expectedRecording` を新鮮に観測した `stopped`、`session`、`arrangement`、
`both` モードに設定して `live_session_emergency_stop` を使用し、再生と両方の
録音モードをクリアします。`recordingStopped=true` と新鮮な停止状態を検証して
ください。

## オーディオキャプチャ監視

キャプチャ前に、正確な Set、ソース/デスティネーションスロット、デスティ
ネーションのルート/arm/モニターベースライン、再生/録音状態、出力安全性の
出所、生ファイルディレクトリ数を記録します。ポート/プロセスの存在だけで
監視しないでください。`real-live` の出所とすべての正規キャプチャ操作を
要求してください。

適用中、MCP リクエストは要求された時間に有界なファイナライズ/解析を加えた
時間オープンのままになることがあります。キャンセルは MCP 応答を発行しませんが、
ホストは独立して停止/クリーンアップを継続します。新しいクライアントから
`live_audio_capture_status` を待ってください。ホストが強制終了されてもマッパー
権限は削除されません: Live 側のウォッチドッグが録音を停止し、新しいパッケージ
ホストは正確に観測された ID で `live_audio_capture_emergency_stop` を実行できます。

パスする完了には、マッパー状態 `cleaned`、`playbackStopped=true`、
トランスポート/Session/Arrangement 録音 false、復元されたルート/arm/モニター、
空のデスティネーションスロット、`rawFileUnlinked=true`、WAV/ASD 残留物なし
が必要です。確認、マッパー/リカバリートークン、PCM、メディアパスを決して
ログに出力しないでください。[AUDIO_INTELLIGENCE.md](AUDIO_INTELLIGENCE.md)
を参照してください。

## デリバリーライフサイクル監視

`ableton-mcp-lifecycle` を使用してください。直接の Remote Script コピーは
低レベルの開発プリミティブであり、完全な製品ライフサイクルではありません。
必ず非変更のプランを確認し、インストール/アップグレード/ロールバック/
アンインストールの前に Live を明示的に停止し、正確な tarball SHA、レシート、
ジャーナル、隔離パスを保持してください。ロールバックが利用可能な間は、
レシート外でバックアップを削除または編集しないでください。

変更後、ステータスは一致する管理対象ハッシュ、オーナー専用シークレット権限、
必要に応じて停止/アンロードされた Live、および手動での Control Surface 選択と
認証済み実 Live アクティベーションまでの `restartRequired` を示さなければ
なりません。`activated` にはレジストリ ID と `real-live` の出所が必要です。
空きポート、プロセス、偽マッパー、シミュレーターはこれを満たしません。修復は
ドリフトを隔離し、欠落したシークレットを捏造しません。アンインストールは
デフォルトで変更/不明なコンテンツとシークレットを保持します。正確なコマンドと
Windows/macOS パスポリシーは [DELIVERY.md](DELIVERY.md) にあります。

## エビデンスの境界

Node/Python テスト、シミュレーター、fake-Live マッパー、認証済みループバック
チェック、パッケージ検証、ベンチマークは、リポジトリで制御された契約のみを
確立します。実際の Ableton Live バージョン、使い捨て Set、可視 UI 状態、
可聴/リアルタイム動作、ハードウェア、アクセシビリティ、インストーラー
ランタイム、署名、公証、リリース準備を証明するものではありません。
