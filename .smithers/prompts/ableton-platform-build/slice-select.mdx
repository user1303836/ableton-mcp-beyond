# Slice Select

Choose the highest-risk bounded failing matrix rows and derive dependency-aware, non-overlapping implementation work with acceptance commands.

This workflow exists to build the comprehensive Ableton platform, not merely to polish the locally testable MCP shell. **The absence of a Live adapter, Extension, Remote Script, Max device, fixture, test harness, platform package, or UI is implementation work to select—not a reason to defer that domain.** After the host foundation exists, every iteration must materially expand at least one unsupported core Ableton-control domain and one end-user workflow. A slice that only refactors transport, analysis math, tests, packaging, or documentation is invalid unless a concrete external blocker makes all core-domain scaffolding impossible; record exact evidence if that exceptional case occurs.

Use this dependency-aware breadth progression, revisiting earlier stages when review finds defects:

1. A real cross-platform Ableton bridge boundary with deterministic CI mock plus installable Python Remote Script/control-surface and/or Ableton Extension implementation, authenticated loopback transport, capability negotiation, stable object references, subscriptions, reconnection, and diagnostics.
2. Comprehensive read/discovery snapshots for Song, application/UI, Session and Arrangement, tracks/scenes/clip slots/clips/notes/audio/warp/takes, devices/racks/chains/drum pads/parameters, browser, routing, mixer, automation/modulation, locators, grooves, and selection.
3. Previewable, reversible, idempotent mutation transactions with operation journals, confirmation policy, Live undo grouping, compensation, cancellation, dry run, batch semantics, and emergency stop/mute independent of the normal mutation queue.
4. Session and Arrangement creation/editing, MIDI and drum sequencing, audio editing/warping, automation, routing, recording, transport, browser/device loading, rack/device/plugin parameter control, preset workflows, and project management.
5. Reliable audio tap/capture plus waveform, FFT/spectrum/spectrogram, loudness, dynamics/transients, phase/stereo, signal-chain and reference-comparison workflows, with bounded artifact resources and privacy controls.
6. High-rate UDP/event paths, OSC interoperability, Max for Live integration, live-performance controls, generic third-party plugin control, explicit capability-limited UI-assisted fallback, accessibility, and Windows/macOS installers and E2E evidence.
7. Agent-facing creative prompts/resources and complete user journeys: style-informed beat/song creation without copying protected expression, Serum-like patch design, complex drum sequencing, sound-design examples, diagnosis/mix/master/reference workflows, and safe live performance.

Select work that creates missing prerequisites where necessary. Do not wait for an already-connected Live adapter before implementing the adapter and its deterministic simulator/contract tests. Keep ownership non-overlapping, but assign meaningful work to host, Ableton, analysis, and delivery specialists whenever their domains remain incomplete. Acceptance criteria must include behavioral tests and honest evidence labels; unavailable external hardware/signing/Windows/Live observations remain unavailable, while their code, mocks, contracts, installers, and CI can still be implemented and tested.
