# Bounded implementation plan

Plan only the current iteration from requirements, prior findings, PR feedback, validation failures, and remaining budget. Define safe changes, acceptance checks, and deferrals.

The plan must advance the comprehensive Ableton product rather than repeatedly polish the MCP shell. Treat missing adapters, Remote Scripts, Extensions, Max devices, fixtures, installers, and Live test harnesses as work to create. Once the basic host builds, include at least one unsupported core Live-control capability and one complete user-facing workflow in every iteration unless exact external evidence proves no such code, mock, contract, or test can be written. Preserve dependency order: bridge and simulator; broad discovery; reversible transactions; Session/Arrangement/MIDI/audio/devices/routing; audio capture and deep analysis; realtime/OSC/Max/plugin/accessibility/platform delivery; creative agent resources and journeys. Keep the host, Ableton, analysis, and delivery ownership sets non-overlapping and give each specialist substantive work whenever its domain remains incomplete.
